# D5 完全自动化可行性评估（W8 Task 6，2026-08-29）

> 依据：W8 五轮真实运行数据（审批单 output/approvals/ 共 5 份 + PR #3）与三份 SDD 账本。
> 结论先行：**有条件部分自动化可行，完全自动 PR 暂不推荐**——门禁机制已被实战验证有效，但"Agent 正确执行率"仍不足一半，且多数失败模式需要人（或更好的模型/提示词）而非更多自动化来兜底。

## 一、证据：五轮真实运行（Arknights-LLM-wiki Issue #1/#2，知识纠错域任务）

| 轮次 | 结果 | 失败/拦截原因 | 对应防线 |
|------|------|---------------|----------|
| R1（Issue #1） | rejected | 核心未执行（未产出实质修复） | Reviewer FAIL + 人工拒绝 |
| R2（Issue #2 v2） | rejected | 红线违反（generated_at/cost_log 副作用）+ 脚本残留 | 人工拒绝 → 催生 A4 红线机械拦截 + A5 产物纪律 |
| R3（Issue #2 v3，deepseek） | rejected | 模型 DSML 文本化工具调用 → 第 5 迭代假完成早停 | A7 结论审查模式暴露空交付 + 人工拒绝 |
| R4（Issue #2 v4，deepseek） | rejected | 同 R3 模型问题 | 人工拒绝 → 模型切回 mimo |
| R5（Issue #2 v4，mimo） | approved → PR #3 | 正常：删除 2 条已核验死数据；A4 拦截 red_line_reverts=2 并入审批单 | Reviewer FAIL 后修复重跑 + 人工批准 |

## 二、门禁有效性（已实证）

- **Reviewer 独立审查**：R1/R2 的"核心未执行/交付不完整"均被 Reviewer 先行捕获，无幻觉论据（A3 生效）。
- **红线机械拦截（A4）**：运行期副作用文件被自动还原并计入审批单（R5 red_line_reverts=2），人工无需逐文件核对红线。
- **防重放/漂移检查**：rejected 单零远端副作用已实测；diff sha256 指纹拦截仓库漂移。
- **结论交付（A7）**：空 diff + 结论审查模式使"假完成"在审批单层面可见。

## 三、核心瓶颈（限制全自动化的不是流程，是执行质量）

1. **正确执行率 1/5（R5）**：若自动放行 Reviewer PASS 的单，需证明 Reviewer PASS 与真实正确高度相关；当前样本中 R1-R4 全部 FAIL 被人拒，尚无"Reviewer PASS 但人工本应拒绝"的反例——这是部分自动化的正面信号，但样本量 1，不足以放心把 push 权交给机器。
2. **模型层故障（DSML 早停）占了 5 轮中 2 轮失败**：这类失败 Reviewer 能暴露（空交付）但 Agent 无法自愈；自动化只会把无效轮次的成本放大。
3. **域任务判定依赖人工核验**：死数据删除的"正确性"最终来自人工抽查结论（粗筛信号非结论），机器不具备终审资格。
4. **成本**：R5 一轮 61 迭代量级（mimo），自动化重试会线性放大 token 成本，无人在环止损。

## 四、建议（分档自动化）

| 档位 | 条件 | 判定 |
|------|------|------|
| 现状（推荐保持） | Reviewer FAIL → 停等；人工审批 → push | 五轮实证安全 |
| 近期可开（条件自动放行） | Reviewer PASS + red_line_reverts=0 + test 全绿 + 非删除型变更（新增/修复类）→ 自动 PR；删除型/知识写回仍人工 | 依据：门禁已被实证 + 此类变更可回滚 |
| 完全自动化 | 累计 ≥10 轮条件自动放行零事故 + 执行正确率 ≥80%（W6 adjusted 口径）后再评估 | 当前 20%（且受 pytz 类基准缺口低估）远不达标 |

## 五、后续动作

- 条件自动放行的判定字段审批单均已具备（review 结论/red_line_reverts/diff），实现成本低，建议作为独立小任务排期（不新开窗口）。
- 知识纠错第二阶段（--apply 写回）维持人工审批通道（action_type=knowledge_apply 已预留），不受本评估影响。
