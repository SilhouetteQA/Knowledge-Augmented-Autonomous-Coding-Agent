## 二、预算消耗解剖（推断性，无步骤级 trace）

域任务的信息面/动作面远大于代码任务：

1. **探索面巨大**：1199 concepts（v3_final）+ v1_events + stories + md 文件。仅「读数据看结构」就要 10-20 轮工具调用（W1 同款教训：探索阶段 77 文件）。
2. **四阶段任务模型**：全域探索 → 三条件判定 → 删除 → 重建索引+回归。30 迭代下「执行」只分到尾部几个迭代；二轮重试（+31）仍不够——因为**每轮都从探索重新开始**（round 2 的 sync 清掉了 round 1 的全部产物，Agent 无跨轮记忆）。
3. **约束不对称推高判定成本**：A2「任一条件满足即保留」使「证明可删」需要读全三个数据源（md + seed + index）逐条取证；「证明不可删」只需一条证据。风险对称性 → Agent 倾向不删。A4/A5 后违规路径被堵死（成本不可转嫁），A5 堵住脚本辅助后分析只能靠逐轮 read——**零风险策略 = 零动作**（推断：round 2 进入纯探索-验证循环直至上限）。
4. **无 Ground Truth 锚点**：Issue 要求「以实际数据为准」全域自证；而仓库内其实已有上一轮分析产物证明候选存在——信息供给缺口。
5. **模型行为假设（未验证）**：mimo 在「高约束 + 大信息面」下偏分析收敛而非执行推进；对照 schedule 任务约束小、信息面窄 → 正常执行。此假设待单次模型对比实验验证（L5）。

## 三、根因分级

- **R1（确定）任务形态 × 预算**：通用 30 迭代预算不匹配四阶段域任务；探索-执行预算分配失控。
- **R2（确定）约束不对称**：红线/保留规则使「不动作」成为理性稳妥解。
- **R3（确定）跨轮无记忆**：每轮重跑全域探索，前轮分析结论不传递。
- **R4（假设待验证）模型风格**：mimo 在该约束面下的行为倾向。

## 五、建议组合（待用户拍板）

- **首选组合：L1 + L6 + L3**（候选锚点 + 范围收窄 + 阶段预算提示词）：三处均低成本，把任务从「全域四阶段」降为「验证 3 候选 → 删除 → 重建索引 → 回归 → 交付清单」，30 迭代即可容纳；A6 作为代码侧微调一并入库。
- **可选实验：L5**（deepseek 单次对比）——若组合方案仍不收敛，用之一锤定音 R4。
- **暂缓：L4**（工具化）——E9 的 domain_checks 已在评估器侧就位，agent 侧工具化可作为后续窗口；本轮先用提示词与 scope 杠杆。

## 六、评估结论

域任务在「全域探索 + 高约束 + 30 迭代」下对当前管线不可收敛，主因是任务形态（R1/R2/R3）而非单一模型缺陷；L4 之外的杠杆组合可在不改架构的前提下显著提高收敛概率。若组合后仍失败，则 R4 成立，需上 L4 或模型切换。
